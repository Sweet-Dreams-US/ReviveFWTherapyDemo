# Revive on the shared FreeWebsites Supabase project

Moved from the standalone ReviveFW project (ref `xpellfnufhvmqkabvabn`) to
FreeWebsites (ref `nxhwqtqroyerbbklywyn`) on 2026-10-18.

FreeWebsites is shared with other client sites, so the generic table names got
the house `revive_` prefix. Everything else kept its name:

| Old (ReviveFW)            | Now (FreeWebsites)               |
|---------------------------|----------------------------------|
| `public.settings`         | `public.revive_settings`         |
| `public.inquiries`        | `public.revive_inquiries`        |
| `public.jobs`             | `public.revive_jobs`             |
| `public.job_applications` | `public.revive_job_applications` |
| `public.app_secrets`      | `revive_private.app_secrets` (not reachable through the API) |
| `revive_private.*`        | unchanged                        |
| `public.revive_*()` RPCs  | unchanged (same names and signatures) |
| bucket `Images`           | `revive-images`                  |
| bucket `applications`     | `revive-applications`            |
| bucket `icons`            | `revive-icons`                   |

The schema was generated from the live ReviveFW database with those renames
applied, and every function was checked against the source by checksum. It is
recorded in FreeWebsites' migration history as `revive_01_tables` …
`revive_06_function_grants`. The files in `../migrations/` are the original
project's history; new SQL for Revive should target the names above.

`revive_private.meta_lead_events.id` is `generated by default as identity`
(it was `always` before) so existing ids could be copied.
